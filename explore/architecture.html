Bookmark Atlas

It saves your GitHub stars and X bookmarks on your own computer and lets you search them: from the terminal, from AI assistants, or from a palette inside the pi coding agent. One person wrote it in about three weeks, and it needs no outside libraries to run.

The big picture

One database file in the middle, three ways to ask it questions, and importers that fill it.

In plain wordsThink of a personal library. Your saved repos and posts are the books, the database is the shelf. You can ask the librarian by typing a command, through an AI assistant, or in the pi search palette. Importers fetch new books from GitHub and X.

One request, step by step

What happens when you ask: "Is there anything I saved that fits what I am building?"

In plain wordsThe tool does not only search for your words. It also looks at what you are working on right now (git branch, recent changes, the libraries you use) and uses that to pick the best matches.
  1. You run the recall command.The command line recognises it and starts. cli.ts:136
  2. It opens your database.One file in your user folder, closed again at the end. cli.ts:78
  3. It reads your git state.Branch, last 12 commit messages, up to 20 changed files. stage.ts:11-56
  4. It reads your package files.This shows which libraries you use. recall.ts:114
  1. It searches six ways and merges the lists.Task and project context, each against titles, full text and passages. recall.ts:538-546
  2. It drops weak matches and adds bonuses.A match on one of your libraries earns a lot. recall.ts:568-657
  3. It prints the best matches with reasons.Up to 25 results, default 5, as JSON. cli.ts:151-161

Where the data lives

One SQLite file: ~/Library/Application Support/bookmark-atlas/bookmarks.db, about 84 MB.

In plain wordsEvery saved item is a "resource". Around it hang the details: when you saved it, your notes, the downloaded text, and for X posts the media. Removing a bookmark deletes nothing at first. The save is only marked as removed, and the prune command later cleans up orphans.

How results are ranked

Two recipes: a plain word search and the project-aware recall.

In plain wordsSearch splits your words, drops filler like "the" and finds bookmarks containing any of them, with title matches counting most. Recall asks the same question six ways (your task, plus context from your project), merges the lists, gives a big bonus to bookmarks that mention a library you use, and throws weak matches out.

Things to watch

Nothing here is broken. These are the places where a surprise is most likely.

In plain wordsThe most useful finding: search and recall disagree about bookmarks you removed. After that come a few missing safety nets: no retries when GitHub is slow, and no tests for the main switchboard and the browser receiver.
Worth a look
Search still shows bookmarks you removed

A removed bookmark is only marked as removed. recall skips it, search returns it. The same question gives different answers.

recall.ts:234, 261, 280, 426 filter removed saves. In search.ts:125 the marker only changes the date shown. Read in code and confirmed by a second reviewer.
Worth a look
GitHub sync stops at the first hiccup

If GitHub says "slow down" or the network drops once, the sync stops and you start it again. The tool never waits and retries.

Any non-OK answer throws. No retry or rate-limit handling in github.ts, enrich.ts, collector.ts. github.ts:270-271 Read in code
Worth a look
The switchboard and the browser receiver have no tests of their own

No test loads cli.ts, collector.ts, receiver.ts or stage.ts directly. The receiver is the only part that listens on a network port. Indirect coverage is unknown.

How to run it

Commands come from package.json. We did not run them.

In plain wordsYou need Node.js 24 or newer. From a checkout, use node src/cli.ts instead of the installed command. The only secret you must set is the token for the browser receiver. GitHub access reuses your gh login if no token is set.
# from a checkout                          # settings (environment variables)
node src/cli.ts status                     BOOKMARK_ATLAS_DB, BOOKMARK_ATLAS_DATA_DIR   where the database lives
npm test            # node --test          BOOKMARK_ATLAS_GITHUB_TOKEN or GH_TOKEN      else: gh auth token
npm run typecheck   # tsc --noEmit         BOOKMARK_ATLAS_X_CAPTURE_TOKEN               needed for "capture x"
npm run build       # writes dist/         BOOKMARK_ATLAS_TWEETXVAULT_BIN, _DIR         the tweetxvault tool

# installed package
bookmark-atlas recall "task" --repo "$PWD"

CI runs type check and tests on Ubuntu and macOS, then checks the package contents. A tag starting with v publishes to npm. ci.yml release.yml
